## 成果與材料

做完以後：

- ESP32-CAM 放在門口或桌上，電腦即時看到畫面和辨識框。
- 畫面裡連續幾張都出現人，手機收到 Discord 通知，附上當下的截圖。
- 同一個人一直待在畫面裡，冷卻時間內不會重複通知。

:::diagram 情境圖 {#scene}
俯視的房間，門口旁的書架上放 ESP32-CAM，鏡頭對著門口；一個人走進門口，畫面範圍用扇形表示。旁邊一台筆電，一支手機跳出通知。
:::

### 做完你會

- 用 Wi-Fi 從板子拿到畫面。
- 讀懂物件偵測的輸出：類別、信心度、框。
- 用「連續幾張」和「冷卻時間」，把一張一張的辨識結果變成一次事件。
- 用 Python 送出附圖片的通知。
- 測出系統在什麼情況下會漏報、誤報。

| 零件 | 數量 | 說明 |

## 系統架構

:::system
裝置：ESP32-CAM｜拍照
→ Wi-Fi
**閘道**：電腦上的 Python｜YOLO26 辨識、判斷事件
→ 網際網路
雲端服務：Discord
→
應用：手機收到通知和截圖
:::

電腦每次向 ESP32-CAM 的 /capture 網址要一張照片，辨識完再要下一張。

和簡易防盜系統比較：

| | 簡易防盜系統 | 簡易 AI 監控系統 |
|---|---|---|
| 感測 | HC-SR04 量距離、光敏電阻量亮度 | 相機拍畫面 |
| 判斷在哪裡 | Uno 上 | 電腦上 |
| 判斷什麼 | 距離變短、變亮 | 畫面裡有沒有人 |
| 板子和電腦怎麼連 | USB 序列埠 | Wi-Fi |

### 系統怎麼判斷

模型每張畫面都會給一次答案，但同一個人站著不動，信心度也會在門檻上下跳。所以不是看到一次就通知，而是：

:::states
沒人｜不通知
→ 連續 3 張都偵測到 person，信心度 0.5 以上
**有人**｜發一次通知，附上截圖
↺ 連續 10 張都沒有偵測到，**回到「沒人」**，重新開始數。
:::

- **冷卻時間**：發過通知後 60 秒內不再發，就算中間回到「沒人」又變成「有人」。
- 這些數字都放在設定檔，測試時再調。

## 動手做

一共 5 個步驟。前 3 步用 ESP32-CAM 和影像辨識講義現成的範例，第 4、5 步用這個專題的監控程式 monitor.py。

::::step 步驟 1｜用電腦鏡頭跑物件偵測 {#step1}
**標籤**：Python
**目標**：確認電腦的 Python、ultralytics 和鏡頭都能用。

#### 程式

用[影像辨識](vision.html#s7)講義的 vision_demo.py，不用改：

```sh
uv run vision_demo.py --task detect
```

#### 完成標準

視窗裡看到自己被框起來，標著 person 和信心度；終端機每秒印一次「detect：person ×1」。

:::fold 常見問題
- **打不開鏡頭**：照影像辨識講義第 07 節，允許終端機使用相機。
- **第一次執行很久沒反應**：正在下載模型檔，約 5 MB。
:::
::::

::::step 步驟 2｜ESP32-CAM 送出畫面 {#step2}
**標籤**：Arduino、2.4 GHz Wi-Fi
**目標**：ESP32-CAM 連上 Wi-Fi，瀏覽器打得開它的畫面。

#### 程式

燒錄 ESP32-CAM 講義的範例 3，燒錄前改 WIFI_SSID、WIFI_PASS。

@code esp32cam/cam_server/cam_server.ino

#### 完成標準

序列埠印出三個網址；手機或電腦打開 `http://板子的IP/capture` 看到一張照片。把這個網址記下來，後面會用到。

:::terms
- **IP 位址**：裝置在網路裡的地址。路由器可能每次分配不同的，以序列埠印出的為準。
:::
::::

::::step 步驟 3｜電腦改看 ESP32-CAM 的畫面 {#step3}
**標籤**：Python
**目標**：同一支 vision_demo.py，畫面來源換成 ESP32-CAM。

#### 程式

```sh
uv run vision_demo.py --task detect --source http://192.168.1.23/capture
```

IP 換成步驟 2 序列埠印出的。

#### 完成標準

視窗裡是 ESP32-CAM 拍到的畫面，人走到鏡頭前會被框起來。比較一下和電腦鏡頭差多少：每秒張數、清晰度、多遠還認得出來。

:::fold 常見問題
- **拿不到畫面：Connection refused／timed out**：電腦和板子不在同一個網路，或 IP 打錯。
- **很卡**：先在 ESP32-CAM 範例 3 把 FRAME_SIZE 改成 FRAMESIZE_QVGA 試試。
:::
::::

::::step 步驟 4｜從一張一張的辨識，變成「有人來了」這個事件 {#step4}
**標籤**：Python
**目標**：照「系統怎麼判斷」的規則，連續 3 張有人才印出「有人來了」，冷卻時間內不重複。

#### 設定檔

在課程資料夾的 config.json 加上 monitor 這一段，capture_url 換成步驟 2 的網址。discord 那一段和簡易防盜系統共用，還沒建 Webhook 也可以先做這一步：沒填的話程式只在終端機印出事件。

@code python/monitor.config.example.json name=config.json

#### 程式

存成課程資料夾裡的 monitor.py：

@code python/monitor.py

```sh
uv run monitor.py
```

沒有板子時，用電腦鏡頭也能測判斷和通知：`uv run monitor.py --source 0`。

:::fold AI 你可以請 AI 幫你這樣做
```prompt
我有一支 Python 程式，每次呼叫 get_frame() 會拿到 ESP32-CAM 的一張畫面（OpenCV 的 BGR 影像），用 ultralytics 的 yolo26n.pt 做物件偵測。
請幫我加上判斷：連續 3 張都偵測到 person（信心度 0.5 以上）才算「有人來了」，印出時間；連續 10 張都沒有才算「人走了」。發生「有人來了」之後 60 秒內不要再觸發。
這些數字從 config.json 的 monitor 讀。用 uv run 執行，不要用 pip。
```

#### 拿到程式後先檢查

- 「連續」有沒有在中間斷掉時歸零。
- 冷卻時間用的是 time.monotonic() 或 time.time()，不是數張數。
- 沒拿到畫面（網路斷了）時不會當掉，也不會被當成「沒人」。
:::

#### 完成標準

走進鏡頭前，2 秒內終端機印出一次「有人來了」；站著不動不會一直印；離開畫面幾秒後印「人走了」。

:::terms
- **事件**：系統要回應的一件事。模型每張畫面都有結果，但「有人來了」只算一次。
- **冷卻時間**：觸發後一段時間內不再觸發，避免通知洗版。
:::
::::

::::step 步驟 5｜發 Discord 通知，附上截圖 {#step5}
**標籤**：Python
**目標**：「有人來了」時，把當下的畫面加上辨識框，傳到 Discord 頻道。

#### 程式

步驟 4 的 monitor.py 已經包含這一段，config.json 的 discord.webhook_url 填好就會發。

#### 完成標準

走進鏡頭前，手機在 5 秒內收到通知，圖片上有框；站在畫面裡 3 分鐘，只收到一則。

> [!NOTE]
> Discord 免費帳號上傳檔案的上限是 10 MB。程式把截圖的長邊縮到 800 像素、存成 JPEG，大約 50–130 KB。

:::fold 常見問題
- **發太快被限流（429）**：短時間發太多則，Discord 會要你等幾秒。冷卻時間就是為了避免這件事。
- **Webhook 無效（401／404）**：網址被刪除或複製不完整，照簡易防盜系統步驟 7 重建。
:::
::::

## 整合驗收

| 項目 | 怎麼做 | 記錄什麼 |
|---|---|---|
| 漏報 | 用平常的速度走過鏡頭前 10 次 | 收到幾則通知 |
| 漏報 | 背對鏡頭、戴帽子、彎腰走過，各 5 次 | 收到幾則 |
| 距離 | 站在 1 m、3 m、5 m | 信心度多少、有沒有觸發 |
| 光線 | 關燈、拉上窗簾 | 有沒有觸發 |
| 誤報 | 沒人的房間放 1 小時 | 誤觸發幾次 |
| 誤報 | 對著播放有人的電視、海報 | 有沒有觸發 |
| 冷卻 | 站在畫面裡 3 分鐘 | 收到幾則 |
| 延遲 | 從走進畫面到手機跳出通知 | 幾秒 |
| 斷線 | 拔掉 ESP32-CAM 的電 | Python 有沒有發現、會不會當掉 |

誤報太多，看的人會把通知關掉；漏報太多，系統就沒有用。調門檻和連續張數時，兩個數字要一起看。

## 什麼情況下會失效

> 「我做的東西在什麼狀況下會翻車？」

每一步的常見問題發生在製作時；這一節是系統裝好以後，在真實情況下會失效的地方。

:::fails 裝置：ESP32-CAM
- **鏡頭被遮住或轉了方向**：畫面裡沒有人，系統只會覺得「沒人」，不會通知。
- **房間太暗**：ESP32-CAM 沒有夜視，人變成一團黑影，認不出來。
- **斷電、重新開機**：IP 可能改變，Python 一直拿不到畫面。
- **Wi-Fi 斷線或太遠**：畫面延遲好幾秒，或完全斷掉。
:::

:::fails 辨識與判斷
- **背對、被遮住、離太遠、走太快**：信心度不夠，或連續張數不夠，漏報。
- **電視、海報、手機螢幕裡的人**：一樣被當成人，誤報。
- **貓、狗走過**：不是 person，不會通知；如果你要偵測的是寵物，就要改類別。
:::

:::fails 閘道與通知
- **電腦休眠、關機，或 Python 當掉**：完全不會通知。「沒收到通知」不代表「沒有人來」。
- **Discord Webhook 網址外流**：別人可以用它往你的頻道發訊息。
- **通知太多**：看的人開始忽略。
:::

:::fails 隱私
- **拍到別人**：在家裡用，要讓家人知道鏡頭在哪裡、拍什麼；不要對著別人家、公共空間或廁所、臥室。
- **截圖傳到 Discord**：畫面離開你的電腦，存在別人的伺服器上。
- **/capture 網址沒有密碼**：連到同一個 Wi-Fi 的人都看得到畫面。
:::

真正的影像監控系統會用夜視鏡頭、多支攝影機、本機錄影和人工確認補上這些漏洞，也要遵守個人資料的相關規定。這個專題的目的，是讓你親手做出系統，再親手找出它的漏洞。

## 延伸挑戰

- **只看畫面裡的一塊**：例如門口那一塊，框的中心點在範圍內才算。
- **換一個類別**：改 config.json 的 target，偵測貓（cat）、狗（dog）或杯子（cup），COCO 的 80 類都可以。程式印的「有人來了」也要跟著改。
- **舉手才通知**：改用 yolo26n-pose.pt，手腕比肩膀高才觸發。
- **系統自我檢查**：超過 1 分鐘拿不到畫面，或畫面全黑，也發一則通知。
- **板子先篩選**：ESP32-CAM 先做畫面變化偵測（[ESP32-CAM 講義範例 5](esp32-cam.html#ex5)），有變化才請電腦辨識。
- **改用其他通知**：Gmail、Telegram，沿用簡易防盜系統的程式。
