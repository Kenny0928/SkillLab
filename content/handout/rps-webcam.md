## 成果與材料

做完以後：

- 你有一個自己訓練的模型檔 best.pt，認得剪刀、石頭、布。
- 兩個人並排坐在網路攝影機前，按空白鍵倒數「剪刀、石頭、布」，畫面框出兩隻手、顯示誰贏，並且記分。
- 你知道這個模型在什麼情況下會認錯，以及要補什麼樣的照片。

:::diagram 情境圖 {#scene}
兩個人並排坐在筆電前，各伸出一隻手：左邊剪刀、右邊布。筆電螢幕上方有網路攝影機。螢幕畫面裡兩隻手各有一個框，標著 scissors、paper，中間顯示「左邊贏」。
:::

### 做完你會

- 拍出夠多樣的訓練照片。
- 用 AI 輔助標記：先讓模型框，再自己檢查、修正。
- 看懂物件偵測資料集的格式：圖片、標記檔、yaml 設定。
- 用 Ultralytics 從已經訓練好的模型接著訓練，看懂損失曲線、mAP、混淆矩陣。
- 用框的位置做判斷，不只是看類別。
- 測出模型在什麼情況下會認錯，並說出原因。

## 系統架構

:::system
拍照：rps_capture.py｜三種手勢，好幾個人
→
標記：X-AnyLabeling｜AI 先框，自己修正
→
**訓練**：Ultralytics｜接著訓練 yolo26n
→
評估：打分數｜驗證集、自己的手
→
應用：猜拳對戰｜rps_game.py
:::

自己做模型，大部分時間花在資料：拍照、標記、檢查。模型只學得會照片裡有的東西，所以照片要像你真正玩的時候：正面對著網路攝影機、在你的教室、很多不同的人。

### 為什麼用物件偵測

| | 影像分類 | 物件偵測 |
|---|---|---|
| 回答什麼 | 這張畫面是什麼 | 畫面裡有哪些東西、各在哪裡 |
| 兩隻手同時入鏡 | 只給一個答案 | 兩隻手各一個框 |
| 標記 | 每張照片選一個類別 | 每個東西畫一個框、選類別 |

兩人對戰要知道哪隻手是誰的，所以要用物件偵測。

### 遊戲怎麼判斷

:::states
等待｜畫面上即時框出手
→ 按空白鍵
倒數｜畫面顯示 3、2、1
→ 倒數結束
判斷｜每位玩家取出現最多次的手勢，顯示誰贏
↺ 結果顯示 3 秒，**回到「等待」**，記分。
:::

- **分左右**：取信心度最高的兩隻手，用框中心的 x 座標分成左邊、右邊的玩家。畫面左右翻轉成鏡像，像照鏡子一樣：坐在左邊的人，出現在畫面左邊。
- **取多數**：倒數結束先等 0.3 秒，再取約 0.5 秒的畫面，每位玩家取出現最多次的手勢。手剛出完還在晃，只看一張容易認錯，這和微專題 02 的「連續幾張」是同一個道理。
- **只看到一隻手或沒看到**：顯示「沒看清楚，再來一次」，這局不算。

## 動手做

一共 6 個步驟。步驟 1、2 最花時間，建議 2–3 人一組，輪流入鏡和操作電腦。上課時間不夠訓練完，步驟 6 可以先用網路上分享的權重。

::::step 步驟 1｜拍照 {#step1}
**標籤**：Python
**目標**：三種手勢各拍 50 張以上，至少 3 個人入鏡。

#### 程式

存成課程資料夾裡的 rps_capture.py：

@code python/rps_capture.py

```sh
uv run rps_capture.py
```

- 一個人比手勢，另一個人操作鍵盤：按 1 拍 rock、2 拍 paper、3 拍 scissors。
- 按下去以後先倒數 2 秒，接著每 0.5 秒拍一張，共 10 張。
- 連拍的時候一直比同一個手勢，但要一直變化：左手、右手、手心、手背、近、遠、畫面的左邊、右邊。
- 畫面下方顯示每一類拍了幾張。照片存在 photos 資料夾，檔名是 rock_0001.jpg 這樣。
- 可以分好幾次、換好幾個人拍，編號會接著往下，不會蓋掉。
- 拍完按 Q 結束。

#### 怎麼拍才有用

模型只學得會照片裡有的樣子。玩的時候會遇到的情況，拍照時都要有：

- **不同的人**：手的大小、膚色、有沒有戴錶、袖子長短。
- **不同的位置**：坐在左邊、右邊，離鏡頭近、遠。
- **兩隻手同時入鏡**：兩個人比同一個手勢一起拍，模型才看過「畫面裡有兩隻手」。
- **不同的光線和背景**：開燈、關燈，換個座位。

拍到臉沒關係，照片只存在你的電腦；但要先問過入鏡的同學。

#### 完成標準

photos 裡 rock、paper、scissors 各 50 張以上，至少 3 個人的手。

:::fold 常見問題
- **打不開鏡頭**：照[影像辨識](vision.html#s7)講義第 07 節，允許終端機使用相機。
- **拍錯手勢了**：到 photos 資料夾把那幾張刪掉。檔名開頭就是手勢，步驟 3 會照檔名決定類別，拍錯沒刪掉，就會教模型學錯。
:::

:::terms
- **資料集**：一批照片，加上標好的答案。
- **多樣性**：照片裡的人、角度、位置、光線越多種，模型換到新的情況越不容易認錯。
:::
::::

::::step 步驟 2｜用 X-AnyLabeling 標記 {#step2}
**標籤**：X-AnyLabeling
**目標**：每張照片裡的每隻手都有一個框。

X-AnyLabeling 是開源的標記程式，不用帳號，照片和標記都存在自己的電腦。它可以載入 YOLO 模型先幫你框，你只要檢查、修正。

#### 安裝（只要一次）

```sh
uv tool install "x-anylabeling-cvhub[cpu]"
```

- 約 1 GB。用 `uv tool` 裝成獨立的程式，不放進課程資料夾：它用的 OpenCV 和 ultralytics 的不一樣，裝在一起會打架。
- 裝好以後，在任何資料夾都能用 `xanylabeling` 指令。找不到指令的話，執行 `uv tool update-shell`，再重開終端機。

#### 準備自動框手的模型（只要一次）

用 [YOLO 模型家族](yolo.html#s6)講義第 06 節那個 Hugging Face 上分享的手部偵測模型，匯出成 X-AnyLabeling 讀得懂的 ONNX：一種通用的模型格式，不需要 PyTorch 也能用（第 07 節）。在課程資料夾執行：

```sh
uv add onnx onnxruntime onnxslim
uv run yolo export model=https://huggingface.co/Bingsu/adetailer/resolve/main/hand_yolov8n.pt format=onnx
```

模型存成 weights/hand_yolov8n.onnx，約 12&nbsp;MB。再把下面的設定存成課程資料夾裡的 xal_hand.yaml，告訴 X-AnyLabeling 模型在哪裡、認得哪些類別：

@code python/xal_hand.yaml

#### 開始標記

在課程資料夾執行：

```sh
xanylabeling --filename photos --labels hand,rock,paper,scissors
```

下面的快捷鍵寫的是 Windows；Mac 上的 Ctrl 要換成 ⌘（Command）。

1. 按 Ctrl+A 打開「Auto Labeling」面板，在模型選單選「...Load Custom Model」，選課程資料夾裡的 xal_hand.yaml。
2. 按 Ctrl+B（Auto Run），照畫面的提示確認，所有照片都會先框好手。測試筆電上每張不到 0.1 秒。
3. 按 D 看下一張、A 看上一張，每一張都檢查：
   - **框到不是手的東西**：選到那個框，按 Delete（Mac 筆電按 fn + delete）刪掉。
   - **有手沒框到**：按 R 畫一個框，框住整隻手，類別選 hand。
   - **框太大或太小**：按 Ctrl+J 切到編輯模式，拖曳框的角調整。
4. 改過就會自動存檔，標記存成照片旁邊同名的 .json。

AI 只知道「這是手」，不知道是哪個手勢，所以框的類別都是 hand。手勢已經寫在檔名裡，步驟 3 會照檔名決定。照步驟 1 拍的話，一張照片裡的手都是同一個手勢；萬一有一張比了不同的手勢，就按 Ctrl+E 把每個框的類別改成 rock、paper 或 scissors。

> [!NOTE]
> X-AnyLabeling 的介面預設是英文，「Language」選單可以切換成簡體中文，沒有繁體中文。

#### 框要框多大

- 框住整隻手，從指尖到手腕，不要切掉手指。
- 不要多框太多背景，也不用框到手臂。
- 手被擋住一半也要框，框住看得到的部分。
- 同一批照片的標準要一樣：今天框到手腕、明天框到手肘，模型會學不清楚。

#### 完成標準

每張照片都看過，每隻手都剛好有一個框，沒有多餘的框。

:::fold 常見問題
- **選單裡沒有「...Load Custom Model」**：先按 Ctrl+A 打開 Auto Labeling 面板，選單在面板最上面。
- **載入 xal_hand.yaml 時說找不到模型**：weights/hand_yolov8n.onnx 和 xal_hand.yaml 都要在課程資料夾裡；先確認匯出那一步成功了。
- **Mac 說無法打開**：從終端機用 `xanylabeling` 啟動，不要直接點兩下程式。
:::

:::terms
- **標記**：照片的答案。物件偵測的標記是框和類別。
- **AI 輔助標記**：先用模型自動標，人再檢查、修正。比全部自己畫快很多，但模型會錯，一定要一張一張看過。
:::
::::

::::step 步驟 3｜整理成資料集 {#step3}
**標籤**：Python
**目標**：把照片和標記整理成 YOLO 訓練要的格式，看懂標記檔。

#### 程式

存成課程資料夾裡的 rps_data.py：

@code python/rps_data.py

```sh
uv run rps_data.py
uv run rps_data.py --show
```

- 第一行讀 photos 裡的照片和 .json，每一類各分 8 成給 train、2 成給 valid，存到 datasets/rps，寫出 rps.yaml。還沒標記、沒有框的照片會列出來，這次不用。
- 第二行隨機挑 6 張，照整理好的標記畫出框，存成 rps_show_1.jpg 到 rps_show_6.jpg。寫成 `--show valid` 或 `--show train`，就只從那一組挑。
- 回 X-AnyLabeling 改過標記，或多拍了照片，就再執行一次：每次都從 photos 重新整理。

#### 資料集長什麼樣

```text
datasets/rps/
  train/images/    訓練用的照片
  train/labels/    每張照片一個同名的 .txt 標記檔
  valid/images/    驗證用的照片
  valid/labels/
rps.yaml           告訴 Ultralytics 照片在哪裡、每個編號是什麼類別
```

標記檔一行一個框，例如：

```text
0 0.547 0.457 0.529 0.586
```

| 數字 | 意思 |
|---|---|
| 第 1 個 | 類別編號：0 是 rock、1 是 paper、2 是 scissors |
| 第 2、3 個 | 框中心的 x、y |
| 第 4、5 個 | 框的寬、高 |

位置和大小都用照片寬、高的比例表示，0 到 1。照片縮放以後，標記還是對的。

照片分成兩組：

- **train**：訓練用，模型從這些照片學。
- **valid**：驗證用，每訓練完一輪就拿來打一次分數。模型沒學過這些照片，分數才準。rps.yaml 裡寫成 `val:`。

#### 完成標準

終端機印出 train、valid 各有幾張、每一類幾個框，三類都不是 0；--show 存出來的圖上，框剛好框住手，類別也對。

:::terms
- **訓練集、驗證集**：同一份資料分成兩組，一組用來學、一組用來打分數。
:::
::::

::::step 步驟 4｜訓練 {#step4}
**標籤**：Python、Colab（選用）
**目標**：先試跑 3 輪看懂流程，再正式訓練，把 best.pt 放進課程資料夾。

#### 試跑

```sh
uv run yolo train model=yolo26n.pt data=rps.yaml epochs=3 imgsz=320 name=trial
```

- `model=yolo26n.pt`：從官方訓練好的 yolo26n 接著訓練。它已經學會看邊緣、形狀這些基本特徵，只要再學三種手勢長什麼樣，所以幾百張照片就夠。
- `epochs=3`：訓練照片全部看 3 輪。
- `imgsz=320`：照片縮成 320 再訓練，比預設的 640 快，但小的手比較難認。
- `name=trial`：結果存在 runs/detect/trial，和正式訓練分開。

每一輪印兩段：先是訓練的進度，再用驗證集打分數。下面是測試筆電用一份公開資料集試跑的例子，驗證集有 394 張；你的照片比較少，數字會不一樣：

```text
      Epoch    GPU_mem   box_loss   cls_loss    l1_loss  Instances       Size
        3/3         0G     0.6822      1.648     0.0217         11        320: 100% ━━━━━━━━━━━━ 62/62
                 Class     Images  Instances      Box(P          R      mAP50  mAP50-95)
                   all        394        394      0.954      0.945      0.967      0.762
```

| 欄位 | 意思 |
|---|---|
| Epoch | 第幾輪 |
| Instances | 上面是這一小批照片裡有幾隻手；下面是驗證集總共有幾隻手 |
| box_loss、l1_loss | 框的位置和大小差多少，用兩種方法算，越小越好 |
| cls_loss | 類別猜錯多少，越小越好 |
| P（Precision） | 模型框出來的手，有多少是對的 |
| R（Recall） | 照片裡的手，有多少被框到了 |
| mAP50 | 驗證照片上的總分：框和正確答案重疊一半以上、類別也對才算對 |
| mAP50-95 | 更嚴格的總分：框要對得更準 |

#### 正式訓練

```sh
uv run yolo train model=yolo26n.pt data=rps.yaml epochs=50
```

- 有 NVIDIA 顯示卡：在指令最後加上 `device=0`。
- Apple 晶片（M1 以後）的 Mac：在指令最後加上 `device=mps`，用晶片內建的 GPU。Intel 處理器的 Mac 不加。
- 測試筆電只用 CPU 時，imgsz 640 每張照片每一輪約 0.12 秒：300 張照片一輪約 40 秒，50 輪約半小時。一般筆電可能要慢上幾倍，時間不夠就把輪數減少，或改用 `imgsz=320`。
- 訓練完，終端機最後一行印出結果存在哪裡（第一次是 runs/detect/train，再訓練一次是 train-2……），把裡面的 weights/best.pt 複製到課程資料夾。後面的步驟都用課程資料夾裡的 best.pt。

#### 用 Colab（選用）

電腦太慢時，可以借 Google 的 GPU：

1. 把 datasets/rps 資料夾壓縮成 zip：Mac 在 Finder 按右鍵 →「壓縮」；Windows 按右鍵 →「壓縮至」→「ZIP 檔案」。
2. 打開 [rps_train_colab.ipynb](https://colab.research.google.com/github/Kenny0928/SkillLab/blob/main/handout/code/python/rps_train_colab.ipynb)，用 Google 帳號登入。
3. 選單的「執行階段 → 變更執行階段類型」，硬體加速器選 T4 GPU，按「儲存」。
4. 從上到下，一格一格執行；第 2 格會要你選剛才的 zip，筆記本會自己寫好 rps.yaml。
5. 最後一格會下載 best.pt。瀏覽器會把它存到電腦的「下載」資料夾，把它移到課程資料夾。

> [!NOTE]
> Colab 免費版的 GPU 有空才分得到，不保證；閒置太久會斷線，一次最多執行 12 小時。上傳到 Colab 的照片存在 Google 的伺服器上，裡面有同學的臉的話，先問過同學。

#### 完成標準

best.pt 在課程資料夾裡；驗證集的 mAP50 越接近 1 越好。低於 0.8 的話，先回步驟 2 檢查標記，再回步驟 1 多拍。

:::fold 常見問題
- **電腦變很燙、風扇很吵**：訓練會用滿 CPU，正常。插著電源跑。
- **再跑一次結果存到哪裡**：同一個名字已經用過，會存到 trial-2、trial-3……，以終端機最後印出的資料夾為準。
:::

:::terms
- **輪（epoch）**：訓練照片全部看過一次。
- **遷移學習**：從已經訓練好的模型接著訓練，比從零開始快很多，需要的照片也少很多。
- **損失（loss）**：模型的答案和標記差多少。訓練就是一直調整權重，讓損失變小。
- **mAP**：把每一類的準確度平均起來的分數，0 到 1（有時寫成 0 到 100）。
:::
::::

::::step 步驟 5｜看懂訓練結果 {#step5}
**標籤**：Python
**目標**：用分數和圖找出模型哪裡強、哪裡弱，再用沒拍過照片的人測。

#### 訓練結果的資料夾

打開步驟 4 終端機最後印出的資料夾（第一次是 runs/detect/train）：

| 檔案 | 看什麼 |
|---|---|
| `results.png` | 損失和分數隨著輪數的變化 |
| `val_batch0_labels.jpg`、`val_batch0_pred.jpg` | 同一批驗證照片，labels 畫的是正確答案，pred 畫的是模型的預測，兩張對照看 |
| `labels.jpg` | 每一類有幾個框、框在照片的哪裡 |
| `weights/best.pt` | 驗證分數最好的那一輪 |
| `weights/last.pt` | 最後一輪 |

用 Colab 訓練的話，這些檔案在 Colab 左邊的檔案清單，runs/detect/train 裡面；results.png 在筆記本第 5 格也會顯示。

打開 results.png，看損失有沒有一直往下：

- 訓練和驗證的損失都往下降，分數往上升、最後變平，就是學得差不多了。
- 只有訓練的損失往下、驗證的損失往上，就是過擬合。
- 最後 10 輪訓練的損失會突然掉一截：關掉了「四張照片拼成一張」的訓練技巧（Mosaic），照片變簡單了。這是 YOLOv4 帶進來的做法。

#### 混淆矩陣怎麼看

訓練資料夾裡也有一張 confusion_matrix.png，但它是用很低的信心度門檻（0.001）畫的，連幾乎不可能的框都算進去，數字很亂。用和遊戲一樣的門檻 0.4 重新畫一張：

```sh
uv run yolo val model=best.pt data=rps.yaml conf=0.4
```

結果存在 runs/detect/val 的 confusion_matrix.png。直的一欄是正確答案（True），橫的一列是模型猜的（Predicted）。下面是測試筆電的一個例子：

| | 答案 rock | 答案 paper | 答案 scissors | 答案 background（沒有手） |
|---|---|---|---|---|
| 模型猜 rock | 130 | 1 | 0 | 5 |
| 模型猜 paper | 1 | 120 | 0 | 2 |
| 模型猜 scissors | 0 | 0 | 134 | 4 |
| 模型猜 background（沒框到） | 5 | 1 | 2 | — |

- 對角線是認對的：這個例子 394 隻手認對 384 隻。
- 最下面的 background 列是漏掉的手：照片裡有，模型沒框到。
- 最右邊的 background 欄是多框的：框到沒有手的地方，或同一隻手多框了一次。
- 看你的矩陣：哪一類最常被認成哪一類？打開 val_batch 的圖，找出是哪種照片。

#### 用沒拍過照片的人測

驗證集的照片，和訓練照片是同一批人、同一個地方拍的，分數會偏高。找一個沒入鏡拍照的同學來測：

```sh
uv run yolo predict model=best.pt source=0 show=True
```

手心朝鏡頭、手背朝鏡頭、側面，近一點、遠一點，各比幾次，記下哪些時候認錯。在終端機按 Ctrl+C 結束。

#### 完成標準

說得出：哪一類最常認錯、被認成什麼；換成沒拍過照片的人，大概還有多準。

:::terms
- **混淆矩陣**：一張表，列出每一類被認成每一類的次數。
- **過擬合**：模型把訓練照片背起來，換一張沒看過的就認不出來。訓練集的損失一直降、驗證集的損失卻開始升，就是過擬合。
:::
::::

## 整合驗收

| 項目 | 怎麼做 | 記錄什麼 |
|---|---|---|
| 每種手勢 | 一個人對著鏡頭，石頭、布、剪刀各比 10 次 | 認對幾次、認錯的被認成什麼 |
| 沒拍過的人 | 找 3 個沒入鏡拍照的同學 | 認對幾次 |
| 角度 | 手心朝鏡頭、手背朝鏡頭、側面 | 認對幾次 |
| 距離 | 手離鏡頭 30 cm、1 m、2 m | 信心度多少 |
| 光線 | 開燈、關燈、背對窗戶 | 認對幾次 |
| 換地方 | 換到另一間教室，或家裡 | 認對幾次 |

| 兩個模型 | 同樣的測試，自己訓練的和網路上分享的各做一次 | 哪個準、差在哪裡 |

## 什麼情況下會失效

> 「我做的東西在什麼狀況下會翻車？」

每一步的常見問題發生在製作時；這一節是做好以後，換到真實情況下會失效的地方。

:::fails 資料
- **只學過拍照那幾個人的手**：換了手很大、很小、膚色不同、戴手套的人，就可能認錯。
- **只學過你的教室**：換了背景、光線，模型沒看過，容易漏掉或認錯。
- **只學過三種手勢**：比讚、比 OK，模型可能硬認成三種之一。
- **標記不一致或拍錯手勢沒刪**：模型會學到錯的答案，而且驗證集分數看不出來，因為驗證集的答案也是錯的。
:::

:::fails 判斷
- **手勢比到一半**：石頭正要變布，兩種都像，取多數也可能取錯。
- **兩隻手靠太近或交疊**：框黏在一起，左右分錯。
- **畫面裡超過兩隻手**：只取信心度最高的兩隻，旁邊同學的手可能被當成玩家。
- **慢出**：倒數結束後才換手勢，程式還是會算。
:::

:::fails 隱私與授權
- **照片拍到同學的臉**：照片只存在自己的電腦；要上傳到 Colab 或分享給別人，先問過入鏡的同學。
- **訓練出來的權重**：Ultralytics 官方說法是 AGPL-3.0，見 [YOLO 模型家族](yolo.html#s8)第 08 節。
- **自動框手的模型**：Hugging Face 上的 Bingsu/adetailer，模型卡標示 Apache-2.0，但它是從 Ultralytics 的 YOLOv8 繼續訓練來的。
:::

準確度不夠，最有效的方法通常不是換大的模型，而是補上缺的照片：認錯的那種人、那種角度、那個地方。

## 延伸挑戰

- **加上公開資料集**：執行 `uv run rps_data.py --kaggle`，下載 Kaggle 上的剪刀石頭布資料集，再用 `data=rps-both.yaml` 把公開資料集和自己的照片一起訓練，比較有沒有比較準。驗證集只用自己的照片，因為要知道的是在你的教室準不準。見下面「我們試過公開資料集」。
- **跟電腦猜拳**：一個人玩，電腦隨機出拳。
- **加新的手勢**：例如「剪刀石頭布蜥蜴史巴克」多出的兩種。要多拍兩種照片，也要改 rps_data.py 和 rps_game.py 裡的類別清單和輸贏規則。
- **換大一號的模型**：檔名的 n 是最小的 nano，s 是大一號的 small（[YOLO 模型家族](yolo.html#s3)第 03 節）。用 yolo26s.pt 接著訓練，比較準確度和速度（第 05 節）。
- **匯出成 ONNX**：見 [YOLO 模型家族](yolo.html#s7)第 07 節。

### 我們試過公開資料集

寫這份講義時，我們先用 Kaggle 上的公開資料集 [cubeai/rock-paper-scissors-detection-for-yolov8](https://www.kaggle.com/datasets/cubeai/rock-paper-scissors-detection-for-yolov8)（約 2,000 張，標示 CC0）訓練。驗證集的 mAP50 有 0.977，但對著網路攝影機玩，只有石頭認得出來。原因：

- **照片全部是同一個人**，用手機從自己的角度往下拍自己的手背，手上戴著錶，手佔了畫面一半以上。網路攝影機看到的剛好相反：正面、手比較小、手心朝鏡頭。
- **測試集的標記有很多畫錯**：592 張裡約 6 成的框沒框在手上，所以測試集的 mAP50 只有 0.22。用 `uv run rps_data.py --kaggle` 下載以後，自己畫出來看看。

測試筆電上，用公開資料集訓練的模型和網路上分享的權重比較（只看認成的手勢對不對）：

| 測試的照片 | 用公開資料集訓練的 | 網路上分享的 |
|---|---|---|
| 資料集的測試照片：自己拍手背，592 張 | 認對 91% | 認對 28% |
| 圖庫裡正面的手勢照片，6 張 | 認對 0 張 | 認對 4 張 |

每個模型只在「跟自己的訓練照片很像」的照片上才準。資料集也會出錯：分數怪怪的時候，先檢查答案，再懷疑模型。這就是這個專題要自己拍照、自己標記的原因。

## 標記工具

這個專題用 X-AnyLabeling。其他常見的標記工具：

| 工具 | 在哪裡跑 | 費用 | 適合 |
|---|---|---|---|
| [X-AnyLabeling](https://github.com/CVHub520/X-AnyLabeling) | 自己的電腦，桌面程式 | 開源，免費；可以載入模型自動標 | 這個專題；照片不想上傳 |
| [Label Studio](https://labelstud.io) | 自己的電腦，用瀏覽器操作 | 開源，免費 | 想全部在自己電腦上做，各種資料都能標 |
| [CVAT](https://www.cvat.ai) | 雲端，或自己架 | 雲端免費版有專案數和空間限制 | 好幾個人一起標 |
| [Roboflow](https://roboflow.com) | 雲端 | 要帳號；[服務條款](https://www.roboflow.com/terms)規定 18 歲以上才能使用 | 老師或大學以上 |

- 匯出時選 YOLO 格式，就是步驟 3 看到的那種 .txt。
- 網路上很多舊教學用 labelImg，它在 2024 年已經停止開發，不建議再用。
- X-AnyLabeling 也能用文字提示自動框，例如選 Grounding DINO 模型、輸入 hand。不過這個模型約 180&nbsp;MB，從 GitHub 下載，網路慢的時候要等很久，所以這個專題用比較小的手部偵測模型。
